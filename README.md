# سیستم مدیریت رزرواسیون و تامین خارجی آژانس مجلل درویشی

اپلیکیشن CRM داخلی با بک‌اند Node.js + Express و دیتابیس SQLite توکار (بدون نیاز به نصب یک سرویس دیتابیس جداگانه مثل Postgres)، مناسب برای اجرا روی هاست/سرور ارزان.

## ۱) اجرای اولیه (روی کامپیوتر خودتان یا سرور)

```bash
npm install
npm start
```

سرور روی پورت 3000 بالا می‌آید: `http://localhost:3000`

**اولین بار که اجرا می‌کنید**، یک کاربر «توسعه‌دهنده» با دسترسی کامل به‌صورت خودکار ساخته می‌شود و نام کاربری/رمز عبورش هم در ترمینال چاپ می‌شود و هم در فایل زیر ذخیره می‌شود:

```
data/INITIAL_DEVELOPER_CREDENTIALS.txt
```

با همین اطلاعات وارد شوید و از منوی «تغییر رمز» بلافاصله رمز را عوض کنید. توصیه می‌شود بعد از اولین ورود، این فایل را از روی سرور پاک کنید.

## ۲) متغیرهای محیطی (برای اجرای واقعی/انتشار)

قبل از انتشار عمومی حتماً این را تنظیم کنید (وگرنه هشدار می‌دهد و از یک مقدار پیش‌فرض ناامن استفاده می‌کند):

```bash
export SESSION_SECRET="یک رشته تصادفی و طولانی و مخفی"
export PORT=3000
```

## ۳) میزبانی روی هاست ارزان

این پروژه فقط Node.js لازم دارد (بدون دیتابیس جداگانه)، پس روی هرکدام از این‌ها قابل اجراست:
- یک VPS ساده (حتی ارزان‌ترین‌ها) با PM2 برای بالا نگه‌داشتن سرور: `pm2 start server.js --name darvishi-crm`
- سرویس‌های Node-friendly مثل Railway، Render، Liara و مشابه (هر کدام که برای شما در دسترس و مقرون‌به‌صرفه‌تر است)
- پشت یک reverse proxy (Nginx) با HTTPS (Let's Encrypt رایگان) — بعد از فعال کردن HTTPS، فقط کافیست در فایل `.env` مقدار `FORCE_SECURE_COOKIE=true` (و `TRUST_PROXY=true`) را تنظیم کنید؛ نیازی به تغییر دستی کد نیست (جزئیات در `SECURITY.md`).

داده‌ها در دو فایل SQLite نگه‌داری می‌شوند — **هر دو را مرتب بک‌آپ بگیرید**:
- `data/darvishi.db`: کاربران، نقش‌ها، تنظیمات، انبار هتل/پرواز
- `data/darvishi-sql.db`: رکوردهای فروش، پیش‌واریزی‌ها، رزروهای تور (جدول‌های واقعی و ایندکس‌دار — `sql/knex.js` را ببینید)

یک اسکریپت آماده هست که **هر دو فایل را با هم** بک‌آپ می‌گیرد: `node backup-db.js` (از API رسمی بک‌آپ SQLite برای هر دو استفاده می‌کند، پس حتی وقتی سرور روشن و در حال نوشتن است هم امن است). بک‌آپ از فقط یکی از این دو فایل ناقص است — نصف اطلاعات کسب‌وکار شما را جا می‌گذارد. راهنمای زمان‌بندی خودکارش در `SECURITY.md` آمده. چون این تنها نسخه از اطلاعات شماست.

## ۴) سطح دسترسی‌ها (RBAC)

- فقط کاربر با نقش «توسعه‌دهنده» به تب «سطح دسترسی» دسترسی دارد. همان‌جا می‌توانید:
  - نقش‌های جدید بسازید (مثلاً «حسابدار»، «مدیر فروش»)
  - برای هر نقش، به‌ازای هر بخش از سیستم (ثبت جدید، رکوردها، بدهی، بستانکاری، پیام‌رسان، گزارش، تنظیمات...) جداگانه مشخص کنید «مشاهده» و/یا «ویرایش» مجاز است یا نه
  - کاربر جدید بسازید و به هرکدام از نقش‌ها متصل کنید، رمز عبورشان را ریست کنید یا غیرفعالشان کنید
- نقش توسعه‌دهنده همیشه دسترسی کامل دارد و از طریق UI قابل محدود کردن نیست (طبق درخواست شما، این نقش فقط برای شماست).
- برای پیام‌رسان/مرخصی: به‌صورت پیش‌فرض هر کاربر فقط گفتگوهایی را می‌بیند که خودش فرستنده یا گیرنده آن است. برای اینکه یک نقش (مثلاً «مدیر داخلی») همه گفتگوها و درخواست‌های مرخصی را ببیند، در تب سطح دسترسی، تیک «این نقش تمام گفتگوها را می‌بیند» را برای آن نقش بزنید.

## ۵) امکاناتی که در این نسخه اول پیاده‌سازی شده

- ورود با نام کاربری/رمز عبور + کپچای ساده ریاضی
- مدیریت کاربران و سطح دسترسی (RBAC) با ماتریس مشاهده/ویرایش برای هر بخش
- ثبت واچر و رزرو (پرواز رفت/برگشت، هتل، کارگذار، ارز، هزینه خدمات)
- پیش‌واریزی (قبل از صدور واچر) و اتصال بعدی آن به یک رکورد
- رکوردها: جستجو/فیلتر، افزودن واریزی جدید (اقساطی)، ویرایش، حذف، علامت «نیاز به اصلاح»
- **سود** هر رکورد = مبلغ کل فروش − (هزینه هتل به ریال + هزینه پرواز رفت/برگشت به ریال) — در جدول رکوردها و گزارش عملکرد نمایش داده می‌شود
- بدهی به کارگزاران (بر اساس هزینه هتل/خدمات هر واچر) با امکان تسویه گروهی و بازگردانی
- بستانکاری از آژانس‌ها (بر اساس مبلغ فروش منهای واریزی)
- پیام‌رسان با **درخواست مرخصی** به‌عنوان یک نوع پیام؛ فقط فرستنده/گیرنده (یا نقش‌های با دسترسی کامل پیام‌رسان) گفتگو را می‌بینند؛ گیرنده می‌تواند مرخصی را تایید/رد کند
- گزارش عملکرد با نمودار (Chart.js): مقایسه کارشناس/کانتر/آژانس/کاربر ثبت‌کننده از نظر فروش، هزینه و سود، به‌همراه روند زمانی روزانه/هفتگی/ماهانه/سالانه
- تنظیمات پایه: آژانس‌ها، کانترها، کارشناسان تأمین، ارزها، شهرها + هتل/کارگذار هر شهر، نرخ روزانه ارز
- **تقویم گرافیکی شمسی** برای همه‌ی فیلدهای تاریخ برنامه (واریزی‌ها، درخواست مرخصی، نرخ ارز، توضیح‌ساز)
- **خروجی اکسل و PDF** از تب رکوردها و تب بدهی (همان روش قبلی: اکسل با کتابخانه‌ی SheetJS در مرورگر، PDF با چاپ مرورگر — قابل ذخیره به‌عنوان PDF)
- **توضیح‌ساز و درخواست لینک**: تولید متن آماده کپی برای پرواز/هتل یا درخواست لینک پرداخت، دقیقاً مثل نسخه‌ی محلی قبلی، با تقویم شمسی و امکان خروجی تاریخ به‌صورت میلادی در متن در صورت نیاز
- **وضعیت پرسنل / مود روز (BRB)** 🎭: هرکس می‌تواند وضعیتش («پای میزم»، «رفتم بیرون»، یا هر چیز دلخواه) و مود امروزش («امروز بی‌حوصله‌ام»، «امروز مود مهربونم» و...) را برای بقیه ثبت کند. اگر مرخصی کسی توسط مدیر تایید شده باشد و امروز در بازه‌ی همان مرخصی باشد، وضعیتش خودکار روی «🌴 مرخصی است» می‌رود، حتی اگر خودش چیزی ثبت نکرده باشد.
- **تعریف هتل و پرواز (انبار نرخ) — فاز اول از سیستم رزرواسیون تور**:
  - برای هر هتل (متعلق به یک شهر) می‌توانید چند نوع اتاق و چند خدمت (صبحانه، ترانسفر و...) تعریف کنید.
  - برای هر اتاق/خدمت، یک **تقویم نرخ شبانه واقعی** دارید — نرخ هر شب را جداگانه با ارز دلخواه ثبت می‌کنید (دقیقاً مثل سیستم‌های رزرو هتل).
  - برای هر پرواز، مبدا/مقصد/تاریخ و ساعت رفت و رسیدن، ایرلاین و شماره پرواز، و چند **کلاس نرخی** (مثلاً Economy/Business) با ظرفیت صندلی و نرخ مجزا تعریف می‌کنید. سیستم جلوی کاهش ظرفیت به زیر تعداد صندلی‌های فروخته‌شده و حذف کلاس نرخی دارای صندلی فروخته‌شده را می‌گیرد.
  - ⚠️ **این فقط بخش تعریف/انبار نرخ است.** موتور رزرواسیون که هتل+پرواز را ترکیب کند، قیمت تور را حساب کند، مشخصات مسافر بگیرد و واچر/بلیت PDF دوزبانه با لوگو صادر کند، فاز بعدی است — که همین‌جا پایین توضیح داده شده.
- **موتور رزرواسیون تور** 🧳 (فاز دوم):
  - انتخاب هتل+اتاق+بازه تاریخ (با محاسبه خودکار قیمت شب‌به‌شب) و/یا خدمات هتل، به‌علاوه پرواز رفت و برگشت.
  - **آبشاری‌شدن کلاس‌های نرخی پرواز**: وقتی چند کلاس نرخی روی یک پرواز تعریف شده باشد (مثلاً ۲ صندلی ارزان، بعد ۲ صندلی گران‌تر، بعد بقیه با نرخ دیگر)، سیستم صندلی‌ها را دقیقاً به همان ترتیب تعریف‌شده تخصیص می‌دهد و وقتی یک کلاس تمام شد خودکار می‌رود سراغ کلاس بعدی. کلاس‌ها را می‌توانید در تب «پرواز و هتل» جابه‌جا (بالا/پایین) کنید تا ترتیب اولویت فروش را عوض کنید.
  - هر کلاس نرخی هم «نرخ فروش» دارد هم «نرخ نت» (قیمت خرید از ایرلاین) — سود واقعی هر صندلی از تفاضل این دو محاسبه می‌شود.
  - قیمت‌گذاری چندارزی: هر شب هتل و هر صندلی پرواز با نرخ ارز همان روز (بر اساس تاریخ ثبت‌شده در «تنظیمات > نرخ روزانه ارزها») به ریال تبدیل و جمع می‌شود.
  - فرم کامل مشخصات مسافر: نام و نام‌خانوادگی فارسی و انگلیسی، شماره پاسپورت، تاریخ تولد و تاریخ انقضای پاسپورت (با تقویم شمسی).
  - مبلغ فروش نهایی به مشتری قابل ویرایش است (پیش‌فرض بر اساس نرخ فروش تعریف‌شده) و سود به‌صورت خودکار محاسبه می‌شود.
  - **صدور واچر و بلیت PDF دوزبانه (فارسی/انگلیسی) با لوگوی آژانس** — تولید کاملاً در همان مرورگر شما (بدون سرویس سنگین سمت سرور)، قابل دانلود و چاپ. لوگو و نام انگلیسی آژانس از تب «تنظیمات» قابل آپلود است. **نکته مهم:** این اسناد فقط مبلغ نهایی فروش را نشان می‌دهند — نرخ نت/هزینه/سود که اطلاعات داخلی آژانس است هرگز روی سند مشتری چاپ نمی‌شود.
  - لغو یک رزرو، صندلی‌های آن پرواز را به‌طور خودکار به انبار برمی‌گرداند تا دوباره قابل فروش باشند.
  - ⚠️ این موتور رزرواسیون یک سیستم **مستقل** از «ثبت جدید / رکوردها»ی قبلی است (چون آن سیستم بر اساس تومان و بدون کنترل ظرفیت طراحی شده بود). یعنی الان دو مسیر ثبت فروش دارید: (۱) «ثبت جدید» ساده برای فروش‌های سریع داخلی، و (۲) «رزرواسیون تور» پیشرفته برای تورهای ارزی با کنترل ظرفیت و صدور بلیت. یکی‌کردن این دو در آینده اگر لازم شد، کار برنامه‌نویس بعدی است.
- **تاریخچه/تایم‌لاین هر رزرو** 🕐: هر رزرو تور از لحظه‌ی ایجاد، هر تغییر مبلغ فروش، و لغو را با تاریخ/ساعت دقیق و نام کاربری که آن کار را انجام داده ثبت می‌کند — از دکمه‌ی 🕐 کنار هر رزرو در تب «رزرواسیون تور» قابل مشاهده است.
- **مانیتورینگ و اعلان ورود** 📡 (تب جداگانه، قابل کنترل از «سطح دسترسی»):
  - هر تلاش ورود (موفق یا ناموفق) با زمان، نام کاربری، آدرس IP و مرورگر ثبت می‌شود — یعنی می‌توانید هر ساعت شبانه‌روز ببینید چه کسی وارد شده.
  - نمایش کاربران «آنلاین اکنون» (فعال در ۵ دقیقه‌ی اخیر)، تعداد ورود موفق/ناموفق امروز، و وضعیت سرور (مدت روشن بودن، حافظه، نسخه Node).
  - **اعلان فوری تلگرام (اختیاری)**: اگر یک ربات تلگرام بسازید (از BotFather) و توکن + شناسه چت را در همین تب وارد کنید، با هر ورود موفق یک پیام فوری دریافت می‌کنید — بدون نیاز به باز بودن برنامه.
  - ⚠️ چون تلگرام از سرورهای شما به `api.telegram.org` وصل می‌شود، این بخش را نتوانستم از محیط توسعه‌ی خودم تست کنم (دسترسی شبکه محدود دارم)؛ منطق کد درست و استاندارد نوشته شده، لطفاً یک‌بار بعد از تنظیم روی سرور واقعی امتحان کنید و اگر پیام نیامد خبر بدهید.

## ۶.۵) امنیت

تمام موارد چک‌لیست امنیتی که فرستادید بررسی و پیاده‌سازی شد. جزئیات کامل (چه چیزی در کد انجام شده، چه چیزی باید روی خود سرور اجرا کنید) در فایل **`SECURITY.md`** آمده، به‌همراه یک فایل آماده‌ی Nginx (`nginx-darvishi.conf`) با HSTS و هدرهای امنیتی. خلاصه‌ی چیزهایی که در همین کد اضافه شد:
- محدودسازی نرخ درخواست (Rate Limiting) روی صفحه‌ی ورود
- Helmet برای هدرهای امنیتی HTTP
- کوکی نشست با `sameSite=strict`، و `secure`/`trust proxy` قابل‌فعال‌سازی با متغیر محیطی وقتی پشت HTTPS واقعی هستید
- محدود کردن دسترسی فایل‌های دیتابیس (`darvishi.db`، `darvishi-sql.db` و پوشه‌ی `data/`) به `chmod 600`/`700` در هر بار ذخیره
- پاک‌سازی خودکار فایل رمز اولیه‌ی توسعه‌دهنده به‌محض تغییر رمز
- گوش دادن Node فقط روی `127.0.0.1` وقتی `HOST=127.0.0.1` تنظیم شود (برای استقرار پشت Nginx)

## ۶) کارهایی که همچنان به فاز بعد موکول شده

- بارگذاری گروهی تنظیمات از اکسل
- پشتیبان‌گیری خودکار (طبق تصمیم شما، این را در سطح سرور/هاست انجام می‌دهید، نه در برنامه)
- پیوست فایل در پیام‌رسان/بدهی (رسید واریز و غیره)
- انتخابگر ستون‌های خروجی اکسل/PDF (فعلاً همه‌ی ستون‌های اصلی به‌صورت پیش‌فرض در خروجی می‌آیند)
- یکی‌سازی «ثبت جدید» قدیمی با «رزرواسیون تور» جدید (در حال حاضر دو سیستم جدا هستند، طبق توضیح بالا)
- کنترل موجودی/ظرفیت اتاق هتل (فعلاً فقط ظرفیت صندلی پرواز کنترل می‌شود؛ تعداد اتاق موجود هتل محدود نیست)

## ۷) ساختار پروژه (برای برنامه‌نویس بعدی)

```
server.js            نقطه ورود، تنظیم session و مسیرها
db.js                لایه‌ی دیتابیس (فایل JSON) — نقطه‌ی تبدیل بعدی به SQL فقط همین فایل است
middleware/auth.js   احراز هویت و بررسی سطح دسترسی
routes/*.js          هر فایل، API یک بخش (رکوردها، بدهی، پیام‌رسان، گزارش، ...)
utils/calc.js        فرمول‌های مالی مشترک (سود، بدهی، تبدیل ارز)
utils/jalali.js      تقویم شمسی (نسخه سرور)
public/              فرانت‌اند (HTML/CSS/JS ساده، بدون فریم‌ورک)
public/js/app.js     هسته‌ی برنامه + مسیر بین تب‌ها
public/js/*.js       هر فایل، منطق یک تب
```

هر فایل route فقط از طریق `db.js` به داده دسترسی دارد، پس مهاجرت به PostgreSQL/MySQL بعداً یعنی فقط بازنویسی `db.js` — بقیه‌ی کد دست نمی‌خورَد.
